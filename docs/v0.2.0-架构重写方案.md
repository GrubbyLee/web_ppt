# Showit v0.2.0 架构重写方案：Tauri 桌面端 → WXT 浏览器扩展

状态：已评审通过（历史架构文档；当前实现以 v0.3 代码和用户手册为准）
日期：2026-09-28

> **现状说明**：本文记录从 Tauri 桌面端迁移到 WXT 扩展时的历史决策。文中的“本机观众窗口”是扩展窗口/WebRTC 回环能力，不是第二显示器业务。当前观众通过视频会议软件共享只读观众窗口，或通过 `apps/relay` 中继链接在自己的浏览器观看。

## 1. 背景与目标

v0.1.0 的 Showit 由三部分组成：Tauri 2 桌面壳（React 演示控制台 + SQLite + axum 观众服务 + LiveKit sidecar）、MV3 扩展（Side Panel 遥控 + tabCapture 发布端）、Native Messaging 桥。

本次为颠覆级重写：**本地演示仅使用浏览器扩展实现**，技术框架为 WXT，默认优先满足 Chrome。产品定位不变（真实业务页面优先、本地优先、只读最小权限、观众只看不说的演示工作台）。

目标：

1. 删除 Tauri 桌面端、Native Host、LiveKit sidecar 与全部桌面打包/更新链路。
2. 以 WXT 重建单一 Chrome MV3 扩展，**侧边栏（Side Panel）为演讲者主控制台**，业务页面在真实浏览器标签页中运行。
3. 保留 contracts 数据合同（`packages/contracts`）与 `.showit` 项目包格式，兼容导入 v0.1 项目。
4. 保留核心演示能力：页面/步骤/计时/自动翻页/排练、高风险确认与强制完成、敏感变量、标注与隐私遮罩、离线备用、本机观众屏、请求保护与只读强制、导入审查与信任指纹、预检、版本与排练记录、LCAPIM 样例。

## 2. 关键决策记录

| # | 决策 | 理由 |
|---|---|---|
| D1 | 会话状态机由 background service worker 持有，持久化到 `chrome.storage.session`（崩溃恢复） | SW 会被杀，状态机必须可重建；v0.1 的 session 快照已是纯数据，天然适配 |
| D2 | 计时采用时间戳差值模型（`timerStartedAt` + 累计值），UI 时钟在面板内 500ms tick；自动翻页由面板 tick 驱动评估 | SW 不可靠定时器；时间戳模型让 SW 重启不丢计时；面板关闭=暂停自动翻页（文档化行为） |
| D3 | 业务页面=会话托管标签页：`iframe`/`window`/`extension` 三种 connector 模式统一映射为标签页策略（当前窗口标签 / 独立浏览器窗口 / 无痕窗口） | 扩展无法内嵌任意站点（CSP/XFO），真实标签页是唯一真实画面载体 |
| D4 | 本机观众屏=扩展页面窗口 + offscreen 文档做 tabCapture→canvas 合成→WebRTC 回环分发 | MV3 SW 不能持有 MediaStream；面板关闭不应中断投送；单次捕获多路分发与 v0.1 管线一致 |
| D5 | 标注（激光/圈选）、隐私遮罩、屏幕封面、离线备用改为**会话标签页内的内容脚本 overlay**；观众侧画面经 tabCapture 天然携带 overlay 像素，合成器对遮罩/封面做二次强制 | 演讲者与观众看到同一画面事实；合成器强制保证"遮罩永不泄露"（与 v0.1 双层策略一致） |
| D6 | `readonly-proxy` 语义改由 DNR 只读规则实现（拦截写方法请求）；`request-protection` 保持 DNR 实现 | 扩展无本地代理进程能力；DNR 可达同等"只读/写保护"目标 |
| D7 | 敏感变量存 `chrome.storage.session`（内存态、浏览器关闭即清、不落盘），带过期 | v0.1 存桌面进程内存；SW 会被杀，storage.session 是扩展内等价物且不进项目数据 |
| D8 | LAN 观众 HTTP/SSE/WS 服务与 LiveKit SFU 移出范围；本机观众窗口数量不设软件上限（受屏幕数约束） | 纯扩展无法监听 TCP 端口；SFU 依赖 sidecar 二进制。管线（合成器+WebRTC）保留为未来"导出式观看页+手动连接码"预留 |
| D9 | 面板 UI 不用 antd（自绘 CSS，延续 v0.1 侧栏视觉语言）；工作台页面（标签页内完整编辑器）继续用 antd | 面板空间与加载开销敏感；工作台是全尺寸页面，移植成本最低 |
| D10 | 项目库/版本/排练存 IndexedDB（大离线资产随项目对象结构化克隆）；信任/诊断/活动项目/设置存 `chrome.storage.local`（unlimitedStorage） | chrome.storage 单项大 JSON 有 IPC 上限风险；IndexedDB 无此问题且天然支持大对象 |

## 3. 目标架构

### 3.1 入口（WXT entrypoints）

```
apps/extension/
├─ entrypoints/
│  ├─ background.ts        # SW：会话状态机、消息中枢、标签/捕获/DNR/诊断编排
│  ├─ sidepanel/           # 演讲者控制台（四区垂直布局）
│  ├─ workbench/           # unlisted 页面：项目库+编辑器（普通标签页）
│  ├─ audience/            # unlisted 页面：本机观众窗口
│  ├─ offscreen/           # unlisted 页面：tabCapture+合成器+WebRTC 中枢
│  └─ content.ts           # 会话标签页内容脚本（按需 executeScript 注入）
├─ lib/                    # 纯逻辑（自桌面端移植）
├─ session/                # 状态机（纯函数 reducer）+ 编排器
├─ messaging/              # 扩展内部消息协议（类型化）
└─ components/             # 共享 React 组件
```

manifest：`sidePanel, tabs, scripting, activeTab, tabCapture, storage, unlimitedStorage, declarativeNetRequest, offscreen`；`optional_host_permissions: http://*/*, https://*/*`（运行时按连接器 origin 申请）。无静态 content_scripts。

### 3.2 数据流

```
Side Panel（控制台/视图+动作）
Workbench（库/编辑） ──runtime──┐
Audience 窗口（视频+状态） ──────┤
Offscreen（捕获+合成+分发） ─────┼──▶ Background（状态机+编排+持久化）
会话标签页 Content（overlay+执行）┘        │
                                    tabs/DNR/executeScript/offscreen/storage
```

- 状态变更：background 广播 `session:state {project, session, meta}` 给所有已连接上下文（面板、观众窗口、offscreen），并向会话标签页推送 overlay 状态。
- 动作：面板/工作台发送 `session:action`（类型化 union）→ background `applyAction` → 广播 + 防抖持久化。
- 心跳：面板 500ms `session:tick {uiBlocked}` → background 评估自动翻页（阻塞条件 = 状态机侧条件 + 面板上报 UI 条件 + 业务就绪）。

### 3.3 存储

| 数据 | 位置 | 键 |
|---|---|---|
| 项目库（Workspace[]） | IndexedDB `showit.workspaces` | keyPath `project.id` |
| 项目版本 | IndexedDB `showit.versions` | keyPath `id`，index `projectId` |
| 排练记录 | IndexedDB `showit.rehearsals` | keyPath `id`，index `projectId` |
| 运行会话快照（崩溃恢复） | chrome.storage.session | `showit:runtime-session:v1` |
| 敏感变量 | chrome.storage.session | `showit:runtime-secrets:v1`（带过期） |
| 信任记录/诊断/活动项目/设置 | chrome.storage.local | 沿用 v0.1 键名 |
| 编辑器草稿 | localStorage（扩展页面同源） | 沿用 v0.1 键名 |

无 chrome API 环境（单测）注入内存回退。

## 4. 模块设计

### 4.1 会话状态机（`session/machine.ts`）

将 v0.1 `presentation-store.ts`（zustand）逐动作移植为纯函数 reducer：

- `MachineState = { project, session, rehearsalStartedAt, rehearsalPageMs, presenterEdits, localAudience }`
- `applyAction(state, action, now)`：全部 30+ 动作（页面导航、步骤状态机、计时结算、排练、屏幕模式、标注、遮罩、离线、观众、结束演示）语义与 v0.1 完全一致（含 `withSequence`、`settleTimer`、`settleAutoAdvance`、rehearsalPageMs 结算）。
- 读取器：`elapsedMs / sectionElapsedMs / autoAdvanceElapsedMs` 原样导出。

### 4.2 编排器（background）

- 会话生命周期：begin（信任门禁→建会话→开标签页→开侧栏）、end（结算→合并 presenterEdits 回库→清理 DNR/offscreen/密钥→关闭自开标签页）。
- 标签页策略：页面切换按 URL 模板解析导航；handoff 沿用 v0.1 `tab-handoff` 决策（ignore/block/authorize/handoff）+ 隐私风险探测。
- 内容脚本：`tabs.onUpdated(complete)` 时 `executeScript` 注入（无静态注册、无持久注册）。
- 录制步骤执行：移植 v0.1 background 的 `execute-recorded-step` 流程（navigate 由 tabs.update 执行，其余下发内容脚本，条件轮询 250ms/超时 1–30s）。
- DNR：`request-protection`（登录/登出/切角路径保护）与只读强制（非 GET/HEAD 拦截）。
- 捕获编排：观众窗口打开→确保 offscreen→签发 streamId→offscreen 捕获→逐窗口 WebRTC（信令经 background 中继）。
- 诊断环缓冲（脱敏，7 天/500 条）。

### 4.3 内容脚本（`entrypoints/content.ts`）

移植 v0.1 全部 8 个 `showit-*` 消息（probe/recorder/execute/condition/pick-mask/resolve-masks/cancel/页面桥）与上行事件（privacy-risk/resource-failures/recorded-action），新增 overlay：

- 标注层：激光（指针移动 ~30Hz 节流上报）、圈选（拖拽绘制，持久化进 session）。
- 遮罩层：solid/blur（backdrop-filter），演讲者视角。
- 屏幕封面：black/white/privacy/ended 覆盖标签页（frozen 仅观众侧冻结，演讲者保持实况——与 v0.1 一致）。
- 离线备用层：图片/视频直渲；HTML 复用 v0.1 `createOfflineHtmlDocument`（重写资源为 dataUrl、注入 `default-src 'none'` CSP、违规 postMessage 上报授权流）；overlay 方式保留登录态，业务页彻底打不开时降级为导航到扩展离线页。

### 4.4 Offscreen（`entrypoints/offscreen/`）

- 捕获：`getUserMedia({chromeMediaSource:"tab", chromeMediaSourceId})`（streamId 由 background 签发）。
- 合成：移植 v0.1 `audience-compositor`（黑/白/冻结/隐私封面 + 遮罩强制 + `canvas.captureStream(30)`）。
- 分发：每观众窗口一条 `RTCPeerConnection({iceServers:[]})`（本机回环 host 候选），信令经 background 中继；状态由 background 推送。

### 4.5 侧边栏控制台（`entrypoints/sidepanel/`）

四区垂直布局（延续深色高密度控制平面视觉）：

1. 顶栏：品牌、项目名、页码/章节、状态芯片（计时状态/屏幕模式/观众）、保存状态。
2. 页面区：标题、目的、连接器健康（probe 状态）、离线备用开关、遮罩/标注工具、"在工作台打开"。
3. 步骤+讲稿区：步骤列表（完成/当前/执行态/高风险徽标，可点切换）、"下一步骤"；Markdown 讲稿（rehype-sanitize 渲染/编辑切换、字号调节、保存徽标）。
4. 底部（sticky）：总/本页/本章/剩余计时 + 首页/上页/下页/末页 + 步骤导航 + 计时开始/暂停/重置 + 排练 + 自动翻页 + 屏幕模式 + 观众窗口。

对话框：高风险确认、条件失败强制完成（必填原因）、敏感变量收集、离线网络 Origin 授权、排练备注、设置抽屉（自动翻页秒数、浏览器会话模式、预检报告+健康检查、讲稿导出、诊断）。

### 4.6 工作台（`entrypoints/workbench/`）

移植 v0.1 `ProjectWorkspace/ProjectEditor`：项目列表（新建/复制/导入/导出/删除/信任审查）、页面/脚本/步骤/连接器编辑、发布版本、排练历史、预检（含逐页健康检查）。持久化换成扩展存储门面（API 同名）。

### 4.7 观众窗口（`entrypoints/audience/`）

`chrome.windows.create` 打开的扩展页：`<video>` 消费合成流；离线备用激活时直渲离线内容（观众侧 HTML 禁脚本）；页码/品牌/连接状态角标；ended 封面。

## 6. 范围裁剪（明确不做）

1. LAN 观众 HTTP/SSE/WS 服务、LiveKit SFU、观众审批/踢出/质量统计、网络接口选择。
2. Native Host、Tauri 打包、应用内更新、便携版。
3. 专用浏览器 profile（`dedicated` 模式近似为无痕窗口，需用户在浏览器中允许扩展进入无痕）。
4. 自动翻页在面板关闭后继续（面板=控制台，关闭即暂停自动翻页；计时按时间戳继续）。
5. 全局键盘快捷键（快捷键作用于面板/工作台，不再抢占业务标签页按键）。

## 9. 自评审记录

**Q1 面板那么窄，装得下四区控制台吗？**
风险真实存在。对策：业务画面本来就在旁边的标签页，面板不需要"舞台"区；四区压缩为"状态/页面/步骤+讲稿/计时与导航"，讲稿区可折叠、字号可调；全量编辑引导到工作台标签页。375px 宽度可用性纳入冒烟断言。

**Q2 SW 被杀会不会丢状态？**
状态机每次变更防抖 250ms 写 `chrome.storage.session`，SW 唤醒时从快照重建；计时用时间戳模型，重启不丢秒数。丢失窗口 ≤250ms 且仅限标注类瞬态（laser 本来就是瞬态）。可接受。

**Q3 tabCapture 在 offscreen 里可行吗？**
streamId 由 background 签发（不带 consumerTabId，扩展内任意页面可消费），offscreen 以 `USER_MEDIA` 理由常驻，是社区成熟模式（v0.1 已在 sidepanel 验证同管线）。风险点：Chrome 对 offscreen 理由的校验措辞——理由字符串写明"投送演示画面给观众窗口"。

**Q4 遮罩只在 overlay 画，泄密风险？**
双层策略：标签页 overlay（演讲者视角）+ 合成器强制（观众视角，即使 overlay 未注入也兜底）。比 v0.1（仅合成器）更强。

**Q5 丢掉 LAN 分享是倒退吗？**
纯扩展无法监听 TCP，这是平台硬边界；保留合成器+WebRTC 管线为未来"导出观看页+手动连接码"留路。诚实裁剪优于虚假承诺，已写入用户手册与 README。

**Q6 antd 只进工作台，会不会双 UI 体系？**
是刻意取舍：面板要轻（常驻、小内存），工作台要全（低频、全功能）。视觉令牌（tokens.css）两边共享。

**Q7 `.showit` 兼容性？**
包格式与 argon2id+AES-GCM 加密原样移植，v0.1 项目可直接导入；contracts 不改字段，仅解释文档更新（connector 模式映射、容量字段忽略）。

**Q8 自动翻页依赖面板 tick，算不算架构缺陷？**
权衡结果：备选方案（offscreen 常驻 tick）会常驻隐藏文档、且面板关闭时"无人可见的自动翻页"本身可疑。选择可见性优先，行为文档化。

**结论：方案通过，按 §8 实施。**
