# Showit 发布与回滚

## 1. 发布前门禁

```bash
npm ci
npm run typecheck
npm run test
npm run build
cargo test --manifest-path apps/desktop/src-tauri/Cargo.toml
node scripts/playwright-project-workspace.mjs
node scripts/playwright-smoke.mjs
xvfb-run -a npm run test:extension-browser
npm run test:sfu
npm run release:extension
```

`release:extension` 必须连续执行两次并得到相同 ZIP SHA-256。发布前还要检查 ZIP 包含最新的 `background.js`、`content-script.js`、Side Panel、manifest 和图标。桌面包生成后记录 `.deb`、AppImage、NSIS、便携 ZIP 与扩展 ZIP 的 SHA-256；任何源码重构建都会使旧校验和失效。

发布标签前还必须在真实环境完成 Windows 10/11、Ubuntu 22.04/24.04、Debian 12、Chrome、Edge、Chromium、Wayland/X11、第二显示器热插拔和跨设备 WebRTC 验收。

当前格式只有 `formatVersion: 1`，可以验证普通、加密、篡改和更高版本拒绝，但尚不存在可执行的历史主版本迁移样本。增加格式版本时必须随代码提交旧版本 fixture、迁移报告断言和升级前快照回归。

## 2. CI 配置

源码主仓库：`https://gitee.com/287198991/showit.git`。

当前自动化流水线位于 `.github/workflows/build.yml`，只会在 GitHub Actions 或兼容 Runner 中执行。仅推送源码到 Gitee 不会触发该流水线。使用 Gitee 托管发布时，应在受控 Runner 中执行本文件第 1 节的同一组门禁，并将构建工件上传至实际发布服务；不得把签名私钥写入仓库或流水线配置文件。

发布环境必须显式提供以下值，变量名在不同 CI 系统中保持一致。

GitHub Actions Secrets：

- `TAURI_SIGNING_PRIVATE_KEY`：Tauri updater 私钥，只存于发布环境。
- `TAURI_SIGNING_PRIVATE_KEY_PASSWORD`：私钥密码，可选。

GitHub Actions Variables：

- `SHOWIT_UPDATER_PUBKEY`：与私钥配对的 updater 公钥。
- `SHOWIT_EXTENSION_IDS`：一个或多个逗号分隔的 Chrome/Edge 商店或企业扩展 ID。

创建密钥时只提交公钥，私钥不得进入 Git、安装包、日志或构建工件：

```bash
npm exec -w @showit/desktop tauri signer generate -- -w ~/.showit/updater.key
```

## 3. 标签发布

推送 `v*` 标签后，流水线会：

1. 执行质量门禁。
2. 构建 Linux `.deb`、AppImage、Windows 当前用户 NSIS 和便携 ZIP。
3. 生成 SHA-256。
4. 使用 Tauri updater 私钥签署 Windows/Linux 更新工件。
5. 生成包含版本、日期、说明、平台 URL 和签名的 `latest.json`。
6. 发布 GitHub Release。

上述第 6 步是当前 GitHub 工作流的实现，不代表 Gitee 已配置发布流水线。若发布工件改由 Gitee Release 或独立对象存储承载，须把 `SHOWIT_UPDATER_ENDPOINT` 设置为实际的 HTTPS `latest.json` 地址，并在生成更新清单时将 `--base-url`、`--release-url` 改为真实下载地址。端点可访问性、签名校验和回滚操作全部验证通过后，才能推送 `v*` 正式标签。

NSIS 标签构建会注入安装/卸载钩子，在 `HKCU` 注册或清理 Chrome、Edge、Chromium Native Messaging Host。未配置真实扩展 ID 或更新公钥时，标签构建会直接失败。

## 4. 安装验收

Linux `.deb`：

```bash
sudo apt install ./Showit_0.1.0_amd64.deb
showit
sudo apt install ./Showit_0.1.1_amd64.deb
sudo apt remove showit
```

验收安装、同路径升级、项目数据保留、`.showit` 文件关联和卸载后用户数据策略。AppImage 需验证可执行权限、启动、签名更新和替换后重启。

构建机上的 Xvfb 启动只能验证 AppImage 可执行、WebView 创建和基础路由，不能替代 Ubuntu/Debian、Wayland/X11、真实双屏热插拔或 5/20 人跨设备容量验收。发布记录必须区分本机构建验证与外部平台验收，不得将未执行项标记为通过。

Windows 需验证无管理员权限安装、WebView2 提示、文件关联、三种浏览器 Host 注册、安装版更新、卸载清理和便携 ZIP 不写安装注册表。

## 5. 更新策略

Showit 在项目库启动后检查稳定版。发现新版本时显示当前版本、目标版本、更新时间和变更说明；只有用户确认才下载和安装。演示运行时不提供安装入口。

Windows 安装版与 Linux AppImage 使用 Tauri 签名验证后安装。Linux `.deb` 和 Windows 便携版打开对应 Release 页面下载完整包。更新服务不可用时不影响本地演示。

## 6. 回滚

1. 从 Release 下架错误版本的 `latest.json` 或将 `latest` 指向修复版本，先阻止继续更新。
2. 不复用已发布版本号，不用旧私钥重新签署不同内容。
3. 发布递增版本的修复包作为首选回滚方式，以保持 Tauri 版本比较单调。
4. 必须降级时先导出 `.showit` 备份，再卸载当前应用并安装已验证的完整离线包。
5. 不删除用户 SQLite 数据目录；若数据格式已升级，使用升级前自动快照或 `.showit` 备份恢复。`runtime_sessions` 只用于恢复运行快照，不能替代项目工作库备份。
6. 验证 Native Host 路径、浏览器扩展连接、项目打开、观众链接和签名更新后再恢复发布。

私钥泄露时立即停止更新端点、轮换密钥并通过完整离线安装包迁移到新公钥版本；旧公钥客户端不能直接信任新私钥签名。
