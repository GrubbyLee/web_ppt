# Showit 发布与回滚

## 1. 发布前门禁

```bash
npm ci
npm run typecheck
npm run test
npm run build
xvfb-run -a npm run test:extension-browser
xvfb-run -a npm run test:extension-e2e
npm run release:extension
```

`release:extension` 必须连续执行两次并得到相同 ZIP SHA-256。发布前还要检查 ZIP 包含最新的 `background.js`、`business-tab.js`、侧边栏、工作台、观众窗口、舞台页、manifest 和图标，并记录扩展 ZIP 的 SHA-256；任何源码重构建都会使旧校验和失效。

发布标签前还必须在真实环境完成 Chrome（含无痕窗口模式）、视频会议共享用的观众窗口、远程中继观众链接、真实业务系统连接器（探测/遮罩/录制/请求保护）的手工验收。tabCapture 授权手势（工具栏图标点击 / 右键菜单 / Ctrl+Shift+9）无法由自动化覆盖，必须人工确认观众窗口或中继观看页出现经合成和隐私保护后的画面。发布验收不包含第二显示器或多屏摆放。

当前格式只有 `formatVersion: 1`，可以验证普通、加密、篡改和更高版本拒绝，但尚不存在可执行的历史主版本迁移样本。增加格式版本时必须随代码提交旧版本 fixture、迁移报告断言和升级前快照回归。

## 2. CI 配置

源码主仓库：`https://gitee.com/287198991/showit.git`。

当前自动化流水线位于 `.github/workflows/build.yml`，只会在 GitHub Actions 或兼容 Runner 中执行。仅推送源码到 Gitee 不会触发该流水线。使用 Gitee 托管发布时，应在受控 Runner 中执行本文件第 1 节的同一组门禁，并将构建工件上传至实际发布服务。

流水线不使用签名密钥；扩展完整性由 ZIP SHA-256 与商店/企业分发渠道保证。

## 3. 发布流程

1. 执行第 1 节全部门禁并通过。
2. 更新 `package.json` 与 `apps/extension/package.json` 版本号（wxt 从 manifest 读取版本）。
3. 打标签 `v<version>` 并推送；流水线产出 `showit-extension` 工件（ZIP + SHA-256）并创建 GitHub Release。
4. Gitee 渠道：手动下载工件、复核 SHA-256 后上传。

## 4. 回滚

扩展回滚 = 加载上一个版本的 ZIP（或商店版本历史）。扩展没有持久化 schema 迁移风险：

- IndexedDB（项目库/版本/排练）与 `chrome.storage`（信任/诊断）的键和结构在 v0.2.x 内保持兼容。
- `chrome.storage.session`（运行快照/敏感变量）在浏览器关闭后自动清空，不参与回滚。
- 若未来引入存储结构变更，必须在发布说明中列出手动降级步骤，并在测试中覆盖“新版本写入 → 旧版本读取”的降级用例。
