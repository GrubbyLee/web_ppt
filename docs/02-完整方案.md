# Showit 演示工作台总体方案

## 1. 方案概述

Showit 采用“编辑器、演示运行时、业务连接器、脚本引擎、观众屏同步”五部分组成的产品结构。项目配置是唯一事实源，运行时根据发布版本创建演示会话。

目标形态：

```text
项目编辑器
  -> 页面编排 / URL 配置 / Markdown 脚本 / 演示变量
发布服务
  -> 项目版本 / 权限 / 资源检查 / 发布快照
演示运行时
  -> 顶部控制区 / 中左业务区 / 中右备注区 / 底部计时区
业务连接器
  -> iframe / 新窗口 / 只读代理 / 登录与角色状态
同步服务
  -> BroadcastChannel + postMessage + 会话状态恢复
观众屏
  -> 只显示业务页面、屏幕状态和标注
```

## 2. 产品模块

### 2.1 项目编辑器

编辑器负责项目元数据、页面列表、页面顺序、业务 URL、脚本和默认布局。编辑器与演示运行时使用相同的项目 JSON Schema，发布前进行完整校验。

### 2.2 演示运行时

运行时拆为四个区域：

| 区域 | 默认占比 | 内容 |
|---|---:|---|
| 顶部 | 8% | 项目、连接状态、自动翻页、检查、设置、观众屏和退出 |
| 中左 | 62% | 业务 iframe、页面选择、刷新、登录、标注工具 |
| 中右 | 25% | 标题、目标、Markdown 备注和脚本滚动区 |
| 底部 | 10% | 计时、页码、翻页、开始计时、重置、排练 |

中左和中右之间使用可拖拽分隔线。布局变量统一由 `--stage-ratio` 控制，取值范围 1:1 至 2:1，默认 5:4。

### 2.3 业务连接器

连接器接口建议：

```ts
type PresentationConnector = {
  id: string;
  name: string;
  origin: string;
  entryPath: string;
  mode: "iframe" | "popup" | "readonly-proxy";
  allowedFramePermissions: string[];
  healthCheck?: { method: "GET"; path: string; timeoutMs: number };
  sessionContract?: {
    loginPath?: string;
    logoutPath?: string;
    statusPath?: string;
    messageType?: string;
  };
};
```

默认连接器采用 iframe + `sandbox`。生产演示推荐通过只读代理隔离业务写操作，只放行明确的登录、退出和查询接口。所有 URL、Header 和权限项在发布前校验，禁止在项目配置中保存 Cookie、Token 和密码。

### 2.4 脚本引擎

Markdown 文本和结构化脚本分开保存：

```json
{
  "pageId": "consumer-live-demo",
  "title": "能力使用者：订阅与调用证据",
  "markdown": "## 现场脚本\n\n打开应用与凭证……",
  "steps": [
    {"type": "say", "text": "说明应用与订阅的关系"},
    {"type": "act", "target": "业务页面", "action": "打开订阅中心"},
    {"type": "expect", "text": "看到资源范围和调用记录"},
    {"type": "transition", "text": "进入下一角色"}
  ],
  "fallback": "业务系统不可用时展示离线说明"
}
```

渲染前执行 Markdown 清理；编辑器保存原文，运行时渲染安全 HTML。脚本可在页面切换时定位到第一条未讲解步骤。

### 2.5 会话同步

- 演讲者页创建随机 sessionId。
- 观众页通过 URL 接收 sessionId，再用 BroadcastChannel 建立同源频道。
- 跨源业务 iframe 只通过限定 targetOrigin 的 `postMessage` 回传登录和角色状态。
- 每条同步消息包含 `type、sessionId、seq、at、nonce、payload`。
- 接收方丢弃旧序列号、重复 nonce、错误来源和不同 sessionId 的消息。
- 观众页打开后发送 `ready`，演讲者页收到后重发完整当前状态。

### 2.6 状态机

演示会话状态：

```text
IDLE -> PREPARING -> RUNNING -> PAUSED -> RUNNING
                         |          |
                         v          v
                       ENDED      RECOVERING
```

业务页面状态：`loading、ready、anonymous、role-mismatch、error、blocked`。

观众屏状态：`disconnected、connecting、synced、frozen、black、white、ended`。

自动翻页只有在 `RUNNING + pageReady + noBlockingInteraction` 时计时；打开设置、编辑脚本、标注、观众屏冻结和连接错误都会暂停自动翻页。

## 3. 数据模型

核心表或文档集合：

- `presentation_projects`：项目名称、说明、默认布局、默认连接器、状态。
- `presentation_project_versions`：版本号、配置快照、发布人、发布时间、变更说明。
- `presentation_pages`：页面顺序、标题、URL、连接器、角色、计时、脚本引用。
- `presentation_scripts`：Markdown、结构化步骤、脚本版本和渲染摘要。
- `presentation_connectors`：业务系统来源、代理策略、CSP、沙箱权限和健康检查。
- `presentation_sessions`：sessionId、项目版本、演示者、当前页、计时和观众屏状态。
- `presentation_rehearsals`：排练记录、页面耗时、超时页和备注。
- `presentation_audit_events`：发布、导出、连接器变更、权限变更和会话操作。

## 4. API 设计

建议 API 前缀 `/api/showit/v1`：

| API | 用途 |
|---|---|
| `GET/POST /projects` | 项目列表和创建 |
| `GET/PATCH/DELETE /projects/{id}` | 项目详情和维护 |
| `GET/POST /projects/{id}/versions` | 版本列表和发布 |
| `GET/PUT /projects/{id}/pages` | 页面编排 |
| `GET/PUT /projects/{id}/scripts/{pageId}` | Markdown 脚本 |
| `GET/POST /connectors` | 连接器维护和健康检查 |
| `POST /sessions` | 创建演示会话 |
| `PATCH /sessions/{id}` | 当前页、计时和屏幕状态同步 |
| `POST /sessions/{id}/rehearsals` | 保存排练记录 |
| `GET /sessions/{id}/events` | 会话事件与异常诊断 |

所有写操作使用 `Idempotency-Key`，项目版本使用 `ETag/If-Match`。API 不返回 Cookie、Token、Secret 和完整 Header。

## 5. 安全方案

- iframe 默认开启 `sandbox="allow-scripts allow-same-origin"`；仅在登录确有需要时加入 `allow-forms`。
- 所有 `postMessage` 使用精确 `targetOrigin`，接收时同时校验 `origin、source、sessionId、nonce`。
- URL 只允许 HTTPS 或明确登记的本地开发 Origin；禁止 `javascript:`、`data:` 和任意文件 URL。
- Markdown 使用 DOMPurify 或同等级 HTML Sanitizer；禁止内联脚本、事件属性和任意表单提交。
- 业务页面默认只读代理，业务写接口返回 `SHOWIT_PRESENTATION_READ_ONLY`。
- 连接器健康检查和代理请求记录 traceId，不记录完整请求体。
- 项目权限与发布权限分离；发布版本不可直接编辑。

## 6. 可靠性和兼容性

- 业务 iframe 加载失败不阻塞演示外壳，支持重试和备用页面。
- 观众屏断开后，演讲者仍可继续操作；恢复时由 `ready` 触发状态重放。
- 浏览器刷新后从项目版本和会话快照恢复当前页和计时。
- 页面尺寸不足时，中右备注区优先保留滚动空间；低于 900px 宽度切换到上下布局。
- 跨浏览器优先支持 Chromium 151+、Chrome 企业版和 Edge 当前版本。

## 8. 设计目标

产品设计保持当前演示页的“深色演讲控制台 + 明亮业务页面”关系，但通过统一的间距、状态色、可拖拽分栏、脚本层级和项目管理入口降低复杂度。业务画面优先，备注可快速扫描，控制动作必须在演讲过程中保持可发现和可操作。
