# Showit v0.2.1 内置演示系统方案

状态：已实施并通过端到端验证（2026-09-29）
日期：2026-09-29

## 1. 背景与目标

v0.2.0 内置的 LCAPIM 示例把业务页面指向 `http://localhost:3001`（外部演示工程）。该服务不可用后示例失效。作为独立交付的演示产品，示例必须**完全内置于扩展内部**，并达到两个目标：

1. 开箱即用：无需任何外部服务即可完整演示（含登录、表单、审批等交互）。
2. 成为产品功能的全量验收载体：示例的每一步都在真实使用产品能力（敏感变量、高风险确认、条件验证、自动续跑、标注、遮罩、离线备用、自动翻页）。

## 2. 实验结论（方案的事实地基）

| 实验 | 结论 | 影响 |
|---|---|---|
| E1 `executeScript` 注入扩展自有页面 | ❌ `Cannot access contents of url "chrome-extension://…"` | 演示页必须**原生实现**连接器协议，不能复用注入路径 |
| E2 `tabs.sendMessage` → 扩展页面 | ✅ 带 listener 即正常响应（返回 probe 结果） | 后台的步骤执行/条件轮询/遮罩框选/录制路径**零改动**即可作用于演示页 |
| E3 `tabCapture` 捕获扩展页面 | ❌ `Chrome pages cannot be captured` | 观众窗口对演示页必须**本地镜像渲染**（反而更优：无需捕获授权、矢量清晰） |

## 3. 架构设计

### 3.1 演练业务系统（虚构产品「云枢 · 能力开放平台」）

一个 light 主题的多视图 SPA，作为 WXT unlisted 页面 `demo.html`，hash 路由：

```
#/login          登录页（密码框 → 隐私风险检测/敏感变量填写）
#/overview       平台指挥台（KPI 卡、SVG 趋势图、动态流）
#/portal         能力门户（访客公开视图）
#/marketplace    能力市场（搜索 + 卡片 + 详情）
#/subscriptions  订阅中心（应用身份、订阅表、用量图表）
#/studio         能力工作室（五种录入方式）
#/studio-details 资产详情（端点、双环境、健康检查、版本）
#/registry       资产目录（状态筛选、配额表单、发布/下线）
#/approvals      审批队列（审批动作 → 状态机变化）
#/operations     运行洞察（Trace 表、网关策略、节点健康）
#/admin          用户与组织
#/admin-controls 权限与流程（密钥脱敏、已发布流程）
```

- 交互元素全部带稳定 `data-testid`（定位/录制/执行的前提）。
- 数据为内置 fixtures（客户/API/订阅/审批/Trace/用户），变更保存在页面内存与 sessionStorage（一次演示运行内持续）。
- 视觉：专业 SaaS 控制台风格（浅色业务画面 × 深色控制台的对比是产品定位的一部分），手写 SVG 图表，无新依赖。

### 3.2 演示页 = 连接器协议的原生实现

`demo.html`（会话标签中的交互模式）同时承担三个角色：

1. **业务应用**：完整登录门禁与视图交互。
2. **连接器**：原生注册 `chrome.runtime.onMessage` 处理 `showit-probe / recorder / execute-action / check-condition / pick-privacy-mask / resolve-masks`（E2 证实可达）——后台现有步骤执行、条件轮询、遮罩框选、录制代码路径**零协议改动**。共享 DOM 逻辑提取到 `lib/dom-connector.ts`，business-tab 与演示页共用。
3. **overlay 宿主**：通过 `showit:demo` 端口接收状态广播，本地渲染封面/遮罩/圈选/激光（与 stage 页同模式），圈选经端口上报 `add-circle`，激光经 `stage-laser` 中继观众。

登录态变化通过端口上报 `demo-connector-state {ready|anonymous}` → 驱动 `businessReady`（未登录时自动翻页被阻塞，形成"登录关卡"演示）。

### 3.3 观众镜像

观众窗口检测当前页为 `demo://` 页时，直接以 **mirror 模式**渲染同一套演示视图（只读、跟随当前页），叠加遮罩/圈选/激光 overlay。不发起 WebRTC、不需要捕获授权——内置示例的观众体验零门槛。

### 3.4 URL 约定与合同

- 新保留方案 `demo://<view>`（如 `demo://marketplace`），contracts 的 `businessUrl`/`businessUrlTemplate` 允许该方案（仅字面 view，不允许模板变量/凭据）。
- 后台 `targetUrlForPage` 将 `demo://x` 映射为 `chrome-extension://<id>/demo.html#/x`，`tabKind = "demo"`。
- 真实业务页路径（https/localhost）不受影响。

### 3.5 后台编排差异（tabKind = demo）

| 关注点 | demo 行为 |
|---|---|
| 内容脚本 | 跳过注入（页面原生实现） |
| 连接器状态 | 由页面经端口上报（登录门禁） |
| 步骤执行/条件/框选/录制 | 走既有 `tabs.sendMessage` 路径 |
| tabCapture | 跳过（观众镜像）；切回真实业务页且有观众时再启动 |
| 修复 | 录制目标改为会话标签（会话运行期间不再依赖"当前活动标签"） |

### 3.6 示例项目重写（保留 18 页叙事）

- 章节/收束页 → `fixed`（舞台幻灯片）；8 个演示页 → `business` + `demo://` URL。
- 步骤升级为真实执行链：登录（固定用户名 + **敏感变量密码** + 条件验证）、市场搜索（fill→click→文本条件，含 autoContinue 自动续跑）、资产发布（**高风险确认**）、审批（点击→状态文本条件）、用量/Trace（元素条件）。
- 项目级 `sensitiveVariables: demoPassword`；一个页面配置离线 HTML 备用（离线开关节奏可演示）。
- 旧 LCAPIM 示例（localhost:3001）纳入迁移链：未被用户改动的旧示例自动升级为新内置示例。

## 4. 测试与验收

- 单测：contracts demo:// 校验；示例项目 schema/预检通过；迁移链。
- 既有冒烟：business-tab 行为不回归（dom-connector 提取后）。
- 新 E2E `playwright-extension-demo-e2e.mjs`：**零外部依赖**跑通——启动示例→登录（敏感变量+隐私翻转）→搜索（自动续跑）→高风险发布→审批条件→圈选/遮罩→观众镜像→离线备用→结束清理。
- 旧 E2E 保留（真实 http 业务页路径：注入/探测/捕获引导）。

## 5. 范围与非目标

- 演示连接器为 interactive 模式：DNR 请求保护/只读强制仍属真实连接器能力，不在内置示例演示（文档说明）。
- 演示页不做真实网络请求（纯本地 fixtures）。

## 6. 自评审记录

**Q1 演示页实现连接器协议，会不会与 business-tab 漂移？**
提取 `lib/dom-connector.ts` 共享（定位器/执行器/条件/录制/框选），两个宿主只保留各自的 chrome 胶水；既有 business-tab 冒烟作为回归门禁。

**Q2 mirror 模式与交互页状态不同步怎么办？**
mirror 渲染 fixtures + 会话状态驱动，不镜像登录态——观众在演讲者登录瞬间看到的是既定视图 + （密码填写时的）隐私封面，恰好符合"观众不该看到登录"的产品原则。

**Q3 demo:// 进入合同会不会削弱安全边界？**
demo:// 只指向扩展自身的 demo.html（映射在后台完成，不可指向任意页面）；合同层禁止凭据/查询/模板变量。真实业务 URL 校验不变。

**Q4 自动翻页在 demo 页的阻塞语义？**
未登录（anonymous）→ businessReady=false → 自动翻页等待，正是"登录关卡"的演示点；登录完成后恢复。

**Q5 体积预算？**
演示应用 + 共享 chunk 预计 +50KiB（无新依赖），预算 1200KiB 余量充足（当前 ~894KiB）。

**结论：方案通过，按 §3-§4 实施。**
